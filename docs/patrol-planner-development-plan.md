# 本地管道巡线路径规划应用：开发目标、要求与实施计划

更新：2026-09-15。范围：项目内独立运行的本地巡线规划小应用。

用户最新方向：先完成稳定的人工地图加点巡线版本，再整理为可在 GitHub 发布的通用路线小应用。自动草稿、双侧候选和全局优化暂时移出产品主流程，后续单独开发。后续实施子代理使用 **GPT-5.6-Luna**，主任务负责整体设计、集成和验收。

## 1. 开发目标

输入需要巡检的管线范围、车辆通行条件、出发位置和里程预算，得到沿道路行驶、尽量覆盖目标管线、可以人工调整和复核的巡检路线。

规划对象包括“必须巡检的管段”和“车辆能够行驶的道路”。管线可能在道路一侧、穿越道路、进入厂区，不能把管线折线直接当作车辆轨迹。

区域巡线模式的默认策略：用户绘制一个多边形区域后，区域内或与边界相交的全部管段自动进入“必巡”集合；规划器以这些管段的关联市政道路为车辆行驶候选，允许为覆盖目标产生往返和重复道路里程。覆盖率优先于最短路，最终必须显示已覆盖、未覆盖、不可达及待人工核验的管段。高德单次途经点上限不足时，应拆成多个连续任务，不能静默减少目标管线。

当前首版不自动从管线生成路线点。用户在高德地图上按道路实际通行顺序添加起点、任务点、途经点和终点，人工点位和顺序是唯一规划依据。系统只负责按相邻控制点调用高德、自动分段、拼接路线和计算结果覆盖率。没有道路中心线、车道方向和转向序列时，不把几何角度冒充“右转优先”。

### 折返与多跑路线规则

高德一次性途经点请求只保证按点位顺序找到合法道路连接，不保证在最近路口掉头，也不保证对相邻点采用局部最短的“到点即返”路径。点位落在管线中心线而不是道路／路口时，还会触发较远的道路吸附；单行道、中央隔离、河道桥梁和禁止掉头都会使路线先绕行再返回。

因此，市政巡线的“去程—最近合法路口折返—回程”不能只靠调整 strategy 参数实现。正式实现应先将管线目标匹配到道路中心线、道路侧别和合法掉头路口，再对每个道路服务段生成折返点；必要时按道路段分段请求高德并合并结果。当前版本只能把人工道路点作为候选，路线返回后由人员复核红圈绕行段。

目标优先级：

1. 满足车辆道路通行条件和必须经过的点位。
2. 满足任务里程／时长预算；不可行时明确说明原因，支持拆分任务。
3. 在满足约束的候选路线中，提高目标管段的有效巡检覆盖。
4. 减少无效往返、重复里程、掉头及人工调整工作量。
5. 保存规划依据和路线版本，供实际巡检前复核。

| CAD 转换 | DXF 图层识别、投影参数录入、转换预览；DWG 先转 DXF | 抽查控制点、处理曲线、块引用、重复线及断点 | 已有离线转换脚本；应用内转换向导待开发 |
| 目标选择 | 按道路、管段选择巡检目标；后续增加框选与必巡／选巡分级 | 覆盖分母只使用选中的管段 | 道路／管段选择已实现 |

| 人工布点 | 起点、终点、多途经点；拖动、重命名、删除、排序、闭环 | 点位顺序准确；点位修改使旧算路结果失效 | 已实现，10 点算路已实测 |

| 草稿辅助 | 当前版本不自动生成管线草稿点；可从历史轨迹提取参考点后由人工确认 | 所有最终点位均由人员添加、拖动或确认 | 当前发布版关闭自动草稿 |
| 道路算路 | 按高德机动车路网生成道路轨迹；不走高速、少收费、拥堵策略 | 道路方案来自算路服务；失败时不以直线冒充道路结果 | 已实现，真实接口通过 |
| 车辆规则 | 普通机动车基础规则；后续增加车辆尺寸、限行、禁行区及无人车核准路段 | 无核准路段或车辆信息时，不给出“无人车可执行”结论 | 普通机动车首版；专项限制待接入 |
| 里程预算 | 显示总里程、估时；按上限筛选；后续支持分段／多班次任务 | 超限方案明确提示，不截断路线伪装成达标 | 筛选已实现；自动拆分待开发 |
| 覆盖分析 | 计算沿路线一定距离内的目标管线长度，标记覆盖不足管段 | 按长度加权，重复经过不重复计入；支持阈值调整 | 几何邻近覆盖已实现 |
| 巡检有效性 | 关联左右侧、道路隔离、设备工作范围及需要往返的管段 | 同一条道路两侧管线不能未经判断视为均有效巡检 | 待业务规则与现场标注 |
| 方案比较 | 比较覆盖率、里程、时间；后续比较重复率和掉头成本 | 对候选方案采用同一目标范围和参数 | 首版支持高德实际返回的候选方案 |
| 自动优化 | 管线到道路匹配、补点、双侧候选和全局优化 | 单独建立实验分支和回放数据，不影响人工主流程 | 暂停，后续开发 |
| 保存与导出 | 本机草稿保存、JSON 导入导出、路线 GeoJSON 导出 | 还原点位、参数及目标管段；坐标系标注准确 | 已实现，持续补充边界验证 |

## 3. 必须明确的业务边界

- **本地应用仍使用在线地图服务。** 管线数据、覆盖计算和草稿在本机；地图资源和选定道路点位算路访问高德。
- **管线覆盖不能等同于实测检漏覆盖。** 当前按几何距离估算；设备探测方向、遮挡、车速、风向等条件尚未纳入。
- **地图位置精度有前置条件。** 现有 CAD 推测使用 CGCS2000 高斯投影、40 带、中央经线 120°；数据方仍需确认投影、单位、基准及资料年代。
- **全图资料与计算资料要区分。** 全部 4848 条是 CAD 展示资料，可能含碎片、重叠或冗余，不能把总长度直接当成正式资产台账。
- **首版里程预算是候选方案筛选。** 没有满足上限的方案时明确提示；自动寻找预算内最大覆盖路线、自动拆分任务属于后续优化阶段。
- **首版按普通机动车处理。** 无人车核准路段、专门通行批复、尺寸限制、时段禁行需要独立数据支持。

### 首版坐标契约

| 环节 | 坐标与计算口径 |
|---|---|
| 已有管线 CSV／GeoJSON | 读取 CGCS2000 经纬度，按 WGS84 近似口径转换一次 |
| 高德显示、道路接口、点位草稿 | GCJ-02 |
| 首版覆盖计算 | GCJ-02 坐标作局部平面近似，以米表示距离，属于规划估算 |
| 路线 GeoJSON 几何 | GCJ-02 近似反算为 WGS84，经纬度导出并附转换说明 |
| 原系统业务数据库 | 沿用原有 CGCS2000/WGS84 近似口径；新小应用不改数据库 |

后续正式计算层应统一基准和投影，并用可靠控制点验证距离误差；不能将首版覆盖计算描述为测绘级 CGCS2000 分析。

## 4. 实施步骤

### 阶段一：基础闭环（当前首版）

1. 检查并复用高德配置、线路五／六与 CAD 转换图层。
2. 建立本地服务和地图界面。
3. 实现管线选择、点位编辑及高德多途经点道路规划。
4. 增加里程上限、覆盖估算、覆盖不足管段定位。
5. 增加草稿和路线导出，进行真实接口与页面验证。

验收：能围绕一个真实管线范围完成“选管段 → 布点 → 算路 → 查漏 → 调点 → 保存”闭环。

### 阶段二：形成可信的管线与道路关系

1. 确认 CAD 投影参数，选控制点做叠加校准。
2. 保留管段原始编号，标记重复、断点、曲线和不确定段。
3. 为管段关联可行驶道路、道路方向、道路左右侧及出入口。
4. 标记双侧巡检、必须往返、不可达和需要人工补巡的管段。
5. 将几何覆盖与业务有效覆盖分开展示。

验收：挑选一组路口、双侧管线、隔离带及厂区入口样例，输出可复核的道路关联结果；不确定结果保持待确认。

### 阶段三：约束规划与自动补线

1. 输入巡检车辆类型、基地、闭环要求、里程／时长预算。
2. 设置必巡管段、可选管段、必须经过点、避让范围。
3. 在道路候选中寻找可行的通行顺序，按覆盖缺口补充道路点位。
4. 计算有效覆盖、重复路段、掉头和超限情况。
5. 在必巡不可满足或路线超预算时给出原因，并生成分任务建议。

验收：至少覆盖单向通行、闭环、双侧管线、预算不足、不可达管段五类场景；不静默舍弃必巡管段。

### 阶段四：实地验证与成果固化

1. 使用线路五、线路六的人工路线作为基准进行方案比较。
2. 对照实际车辆通行条件检查转弯、出入口及停车／补巡点。
3. 记录现场反馈并回填道路关联和巡检规则。
4. 固化路线版本、目标管段、坐标说明和验收记录。
5. 根据使用反馈决定是否集成到原系统 GIS 页面。

验收：操作人员能独立制作、复核、导出一条巡检路线；上线执行前完成现场通行和巡检业务确认。

## 5. 子代理分工与文件边界

开发期间由主任务负责需求、接口约定和最终验收；子代理按独立模块工作，避免多人同时修改同一文件。

| 工作包 | 负责内容 | 文件／模块边界 | 交付物 |
|---|---|---|---|
| 主任务 | 需求管理、接口契约、集成、演示和验收 | 开发计划、集成代码、验收记录 | 可运行版本与验收结论 |
| CAD／GIS 数据子代理 | 投影校验、数据清洗、管段编号与道路关联 | CAD 转换脚本和数据处理模块 | 标准管线图层、质量报告 |
| 规划算法子代理 | 路网顺序、必巡约束、覆盖优化、超预算拆分 | 独立规划与评价模块 | 算法接口、场景测试与对比结果 |
| 地图交互子代理 | 框选、点位编辑、道路关联复核、方案对比 | 地图前端模块 | 可操作页面与交互验收 |
| 测试审查子代理 | 坐标、输入校验、异步状态、草稿恢复、回归检查 | 测试文件；生产代码问题交责任方修复 | 缺陷清单、回归结果 |

当前两个只读子代理已完成实现与业务审查；已将草稿 ID、异步状态、导入图层切换等修复交给 GPT-5.6-Luna 子代理。后续实施阶段最多并行推进三个独立工作包，接口变更先汇总再集成。子代理不得回退其他人的改动。

### 模型与额度安排

- 主任务：统一需求、数据约定、模块边界、关键方案判断、合并和最终验收。
- GPT-5.6-Luna 子代理：承担边界明确的前端交互、数据转换、算法子模块、测试和文档任务。
- 每个任务给定输入、负责文件、完成标准及测试命令；只向子代理提供相关上下文。
- 先完成独立模块再集成；不让多个代理重复探索同一问题，不重复运行已经通过且未受改动影响的检查。
- 小修复复用已有合适代理；涉及核心算法决策的结论由主任务复核。

## 6. 本次已验证证据

- 8 项几何／排序／输入校验测试和 4 项服务／数据校验测试通过。
- 线路五范围读取 177 段；CAD 全图读取 4848 条。
- 浏览器实际加载高德底图、管线与 10 个参考点位。
- 高德真实多途经点算路返回一条约 26.67 km 的机动车路线；40m 阈值下显示约 36.6% 几何邻近覆盖。此值仅为当前测试范围与抽点条件的结果，不是最终优化效果。
- 将里程上限从 30 km 调为 20 km 后，页面提示超限约 6.67 km，保留完整路线。

## 8. 通用小应用与 GitHub 后续路线

### 8.1 产品结构

保留一套通用路线编辑能力，根据使用场景增加目标与评价规则。先通过真实需求验证共用部分，不预先建立复杂插件框架。

| 能力 | 通用基础 | 巡查／巡线场景 | 旅游场景 |
|---|---|---|---|
| 目标输入 | 起终点、途经点、必经位置 | 管段、设备点、巡查区域 | 景点、餐饮、住宿等地点 |
| 行驶条件 | 交通方式、路线偏好、里程／时间预算 | 车辆核准道路、巡检方向、补巡要求 | 每日行程强度、交通方式、游玩节奏 |
| 方案评价 | 路程、通行时间、绕行和顺序 | 有效覆盖、漏巡和重复巡检 | 到访顺序、停留时间、每日行程安排 |
| 路书 | 地图、顺序点位、分段导航、时间与备注 | 必巡管段、设备任务、补巡清单 | 每站活动、预约信息和行程备注 |
| 成果保存 | 任务草稿、路线版本、文件导入导出 | 项目内归档 | 个人收藏和分享用文件 |

旅游模式的营业时间、预约、票价等变化信息需要独立来源核实；基础路线规划器不自动承诺这些信息始终准确。

### 8.2 路书最小可用版本

先输出单文件 HTML／打印版 PDF，再按实际需要增加其他格式：

1. 任务名称、日期、路线总览、起终点、里程与估时。
2. 按顺序列出途经点、分段距离、驾驶指引、预计停留时间和备注。
3. 巡线模式附目标管段、覆盖不足清单与人工复核项。
4. 旅游模式附每日分段、景点停留和住宿结束点。
5. 明确坐标系、地图／路线来源、生成时间和版本。

验收：路线编辑页面与路书顺序一致；修改路线后生成新路书；离线打开导出的文字路书仍能查看点位和指引。底图或在线导航链接是否可离线使用单独说明。

### 8.3 GitHub 发布准备

在巡线闭环稳定后单独实施：

1. 提取独立目录和清晰入口，摆脱当前项目的绝对路径依赖。
2. 将私有配置改为用户自行设置的本地配置，提供不含密钥的示例配置。
3. 示例使用人工构造或确认可公开的数据；不包含当前真实管网、内部轨迹、业务文档和开发日志。
4. 增加首次启动说明、演示资料、测试流程、版本与许可文件。
5. 检查拟发布目录和提交历史中是否包含密钥或内部数据。
6. 核实地图服务、地图截图与路书导出的使用条件，明确用户自备地图服务权限及配额。
7. 准备可审阅的仓库内容与发布说明后，再确定实际 GitHub 仓库和发布版本。

公开源码与对外托管网站是两件不同的工作。本阶段只规划，不建立公开仓库，也不上传本项目管线资料。
