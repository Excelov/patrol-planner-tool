# 巡线工坊开放版部署、账户与订阅架构

## 结论

公开给其他用户使用时，应建设为“前端 Web 应用 + 后端 API + 异步导入/算路服务 + 数据库 + 对象存储 + 账户与计费服务”的完整系统。单页网址只能承载界面，不能安全处理 DXF、API Key、权限、账单和多用户数据。

## 两种产品形态

### 1. 私有本地版

适合燃气公司、城建单位和保密管线资料：

- Windows 桌面安装包或内网 Docker 部署
- DXF/GIS 文件和路线数据留在客户环境
- 用户自行配置高德 Key，或由单位统一配置
- 不强制登录互联网；授权通过许可证文件、设备数和有效期控制

### 2. 公有 SaaS 版

适合通用巡查、旅游路线和路书生成：

```text
Web/PWA 前端
  ↓ HTTPS
API 网关 / 认证服务
  ├─ 用户、组织、项目、角色权限
  ├─ DXF/GIS 导入任务队列
  ├─ 路线规划与高德代理
  ├─ 路线、路书、导出接口
  └─ 订阅和用量校验
数据库 + 对象存储 + 审计日志
```

高德 Key 只放在服务端，前端不暴露 WebService Key；按租户统计调用量、文件容量和任务次数。

## 账户和权限

最小模型：`User`、`Organization`、`Membership`、`Project`、`Dataset`、`RoutePlan`、`Task`、`Subscription`、`UsageRecord`、`AuditLog`。

角色建议：

- 组织所有者：账单、成员、授权和数据删除
- 管理员：项目、图层和路线管理
- 规划员：导入数据、加点、生成和导出路线
- 只读/巡检员：查看路线、执行任务、回传记录

所有业务数据必须带 `organization_id`，后端每次查询都进行租户隔离；分享链接使用短期令牌和最小权限。

## 订阅收费

先做三档，不要一开始按复杂功能拆得过细：

- 试用版：少量项目、文件容量和路线调用次数
- 专业版：更多项目、DXF/GIS 导入、路书导出和团队协作
- 企业版：私有部署、SSO、审计、数据不出域、专属配额和服务协议

计费维度可组合：席位数 + 月度路线规划次数 + 文件存储容量。所有限制由服务端校验，前端只做展示。接入支付平台时，支付回调必须幂等，订阅状态以服务端 webhook 为准。

## DXF/GIS 数据策略

- SaaS：对象存储加密，租户隔离，导入任务异步执行，设置保留期限和彻底删除接口。
- 私有版：文件不离开客户网络，许可证控制功能和期限。
- 公开演示：只使用脱敏示例，不上传真实燃气管线。
- 导入批次保存源文件哈希、坐标系、转换参数、软件版本和操作者，保证可追溯。

## 技术落地顺序

1. 当前 v0.x：本地版，手工点位和高德分段规划。
2. v0.5：本地 DXF/GIS 导入服务、设施点识别、坐标核查。
3. v0.8：后端 API、PostgreSQL/PostGIS、对象存储和异步任务。
4. v0.9：登录、组织、角色权限、用量统计和审计日志。
5. v1.0：订阅、支付 webhook、套餐限额、企业私有部署包。
6. v1.1：PWA/移动端采集、巡检执行和路书分享。

## 版本和部署管理

- `main`：稳定版本；`develop`：集成验证；`feature/*`：功能开发。
- 使用语义化版本和 Git tag；数据库迁移、API 版本和前端版本同步记录。
- CI 构建单元测试、导入样例测试、坐标核查测试和容器镜像。
- 公有 SaaS、企业私有版、本地桌面版分别生成构建包，不混用客户数据和 Key。

## 知识产权与合规边界

自研代码、数据模型、覆盖率和路线算法保留著作权；高德地图、路线和 SDK 按其开放平台协议使用。企业客户数据默认归客户，平台只取得履约所需的处理权。上线前准备用户协议、隐私政策、数据处理协议、软件许可协议和第三方服务清单。
